## 二、深度差距分析

### 2.1 人工智能与推理

#### 差距：无结构化推理过程

- 模型输出直接作为回复，无 CoT（思维链）中间步骤
- 无法将模型的"内部思考"与"最终回答"分离展示
- 不支持 Qwen3 的 `reasoning_content`、DeepSeek 的深度思考等原生推理能力
- **影响**：用户无法理解模型推导过程，调试困难，信任度降低

#### 差距：无自适应工具选择

- 工具选择完全依赖模型自身的判断
- 不记录工具使用历史，不基于成功率调整策略
- **影响**：重复无效调用，资源浪费

#### 差距：无调试辅助

- 错误信息原样返回，无自动分析
- 无堆栈跟踪解读、无修复建议生成
- **影响**：代码开发效率低，用户需手动排查错误

### 2.2 代码理解

#### 差距：无 AST / 符号索引

- 工作区按纯文本检索，无代码结构理解
- 无法回答"这个函数在哪里定义？""哪些地方调用了这个方法？"
- **影响**：大仓检索准确率低，跨文件重构困难

#### 差距：无 Git 原生集成

- Git 操作只能通过 bash 工具执行，受安全策略限制
- 无 diff 感知，无提交管理，无分支操作
- **影响**：编辑后无法自动审查变更，工作流断裂

#### 差距：无增量索引

- 每次启动全量扫描，大仓库（>10万文件）耗时数秒
- 运行时文件变更不自动刷新
- **影响**：启动慢，索引数据可能过时

### 2.3 用户界面与体验

#### 差距：GUI 功能不全

- 无文件树浏览器，用户无法直观浏览项目结构
- 无 diff 视图，代码变更无法预览
- 无 MCP 管理界面，配置依赖命令行
- 无会话管理，历史对话无法搜索切换
- **影响**：桌面体验远逊于 Cursor / VS Code + Copilot

#### 差距：无多模态输入

- 无法发送图片进行分析
- 无法粘贴截图
- **影响**：UI 设计、Bug 截图等场景无法处理

#### 差距：无交互式终端

- Shell 命令返回纯文本，无 PTY 支持
- 无法交互式调试、无法实时查看日志
- **影响**：服务器运维、调试场景体验差

### 2.4 记忆与知识

#### 差距：嵌入引擎原始

- FNV-1a 哈希无语义理解
- "苹果"和"iPhone"的向量几乎不相似
- **影响**：记忆检索质量低，相关记忆频繁遗漏

#### 差距：无分层记忆架构

- 所有记忆平铺在同一层级
- 无重要性评分、无自动衰减、无 LRU 淘汰
- **影响**：关键记忆被噪声淹没

#### 差距：无代码记忆

- 记忆用户偏好但不记忆代码结构
- 跨会话丢失对项目架构的理解
- **影响**：每次新对话都需要重新理解项目

### 2.5 工具生态

#### 差距：工具集偏少

- 缺少专用 git 工具
- 缺少数据库查询工具
- 缺少容器/Docker 工具
- 缺少 API 测试工具
- **影响**：垂直场景覆盖不足

### 2.6 安全与合规

#### 差距：Tauri CSP 禁用

- `csp: null` 意味着允许任意脚本执行
- 存在 XSS 风险
- **影响**：生产环境安全风险

## 三、创新功能提案

### 🔥 P0 - 立即实现（高价值，中等工作量）

#### 3.1 原生 Git 工具集成

在 `src/tools/` 中新增专用 git 工具模块：

- `git_status` — 工作区变更概览
- `git_diff` — 查看未暂存/已暂存变更
- `git_commit` — 带消息提交
- `git_log` — 提交历史
- `git_create_branch` / `git_checkout` — 分支操作

**创新点**：工具绕过 bash 安全限制（git 本身是安全的），并在每次编辑操作后自动触发 `git diff` 审查，形成"编辑 → 审查 → 提交"闭环。

#### 3.2 上下文感知代码搜索替换

在 `replace_in_file` 基础上新增 `search_and_replace` 工具：

- 匹配目标行 + 前后文（context lines）精确定位
- 支持正则和精确模式
- 自动规范化空格/引号差异

**创新点**：解决格式化破坏匹配的问题，类似 Claude Code 的 FileEditTool。

#### 3.3 文件树浏览器（GUI）

侧边栏新增文件树面板，由工作区索引驱动：

- 树形目录展开/折叠
- 文件图标按类型区分
- 点击在聊天中插入文件路径作为上下文
- 搜索过滤

#### 3.4 文件附件连通（GUI）

将已声明但未实现的 `<input type="file">` 连接到聊天流程：

- 文件 base64 编码 → 通过 WebSocket 发送
- 服务端注入到提示词上下文中
- 支持拖放上传
- 支持图片预览
