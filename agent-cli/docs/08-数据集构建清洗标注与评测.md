# 数据集构建、清洗、标注与评测

## 1. 为什么数据集决定上限

模型训练里，真正决定效果上限的，通常不是"你有没有最贵的 GPU"，而是：

- **数据是不是干净** — 噪音数据会让模型学到错误模式
- **数据是不是贴近目标任务** — 通用数据无法覆盖垂直场景
- **标注是不是一致** — 标注者之间的不一致会混淆模型
- **评测是不是靠谱** — 没有可靠的评测就无法衡量改进

### 数据质量与模型性能的关系

```
数据质量 ──────────────────────────────────────────
                                                   │
  数据量         低质量数据              高质量数据
  100条    ┌─ 模型学到噪音，效果差 ── 小样本也能出好效果
  1K条     ┌─ 噪音累积，效果缓慢提升 ── 效果稳定提升
  10K条    ┌─ 噪音淹没信号 ── 强模型
  100K条   ┌─ 需要更多算力补偿噪音 ── SOTA 效果
  1M条     ┌─ 性价比极低 ── 边际收益递减
```

核心结论：**数据质量 > 数据数量**。在大多数实际场景下，精心清洗的 1 万条数据比粗糙爬取的 100 万条数据更有价值。

## 2. 数据集从哪里来

### 2.1 三种主要采集策略

```
采集策略
├── 1. Web Scraping（网络爬取）
│   ├── 适用场景：通用语料、开源代码、技术文档
│   ├── 工具：Scrapy, BeautifulSoup, Playwright, firecrawl
│   ├── 来源：GitHub, Stack Overflow, Wikipedia, ArXiv
│   └── 风险：版权问题、噪音大、需大量清洗
│
├── 2. Synthetic Data（合成数据）
│   ├── 适用场景：特定任务、隐私敏感场景
│   ├── 方法：GPT/Claude 生成、模板填充、数据增强
│   ├── 工具：Self-Instruct, Evol-Instruct, DataTune
│   └── 风险：可能引入幻觉、多样性不足
│
└── 3. Human Annotation（人工标注）
    ├── 适用场景：高质量基准、垂直领域
    ├── 方法：众包平台、内部标注、专家标注
    ├── 工具：LabelStudio, Doccano, Prodigy, Scale AI
    └── 风险：成本高、一致性难以保证
```

|---------|---------|---------|---------|---------|

### 2.3 Self-Instruct 方法

Self-Instruct 是一种使用大模型自动生成指令数据的方法：

```
1. 准备种子指令集（~100-200 条人工编写的指令）
2. 从种子集中随机采样作为示例
3. 调用 LLM 生成新的指令
4. 过滤低质量和重复指令
5. 为每条指令生成输入输出对
6. 重复步骤 2-5 直至达到目标数量
```

代码示例：

```python
# self_instruct.py — Self-Instruct 数据生成示例
import json
import random
from typing import List
from openai import OpenAI

client = OpenAI()

def generate_instructions(
    seed_instructions: List[str],
    num_to_generate: int = 20,
    model: str = "gpt-4"
) -> List[str]:
    """基于种子指令生成新的指令"""
    # 从种子集中随机采样 6 条作为示例
    examples = random.sample(seed_instructions, min(6, len(seed_instructions)))
    examples_str = "\n".join(f"- {ex}" for ex in examples)

    prompt = f"""你是一个指令数据集生成器。请参考以下示例，生成 {num_to_generate} 条新的多样化指令。
指令应该覆盖代码编写、代码审查、架构设计、调试、重构等不同场景。

示例指令：
{examples_str}

请生成 {num_to_generate} 条指令，每行一条，不加序号。"""

    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        temperature=0.8
    )

    content = response.choices[0].message.content
    instructions = [line.strip("- ").strip()
                    for line in content.split("\n")
                    if line.strip() and not line.strip().isdigit()]
    return instructions


def filter_instructions(instructions: List[str], min_length: int = 10) -> List[str]:
    """过滤低质量和重复指令"""
    seen = set()
    filtered = []
    for inst in instructions:
        # 去重
        if inst.lower() in seen:
            continue
        # 长度过滤
        if len(inst) < min_length:
            continue
        # 关键词过滤（非指令性内容）
        if not any(inst.startswith(w) for w in ["写", "请", "如何", "为", "实现", "重构", "分析", "生成", "解释", "优化", "调试"]):
            continue
        seen.add(inst.lower())
        filtered.append(inst)
    return filtered
```

## 3. 数据清洗管线

### 3.1 完整清洗管线图

```
原始数据
    │
    ▼
┌─────────────────┐
│ Step 1: 格式统一  │  ← 统一编码(UTF-8)、JSON/CSV/Parquet 格式转换
└────────┬────────┘
         ▼
┌─────────────────┐
│ Step 2: 去 HTML  │  ← 移除 HTML 标签、Markdown 标记、URL
│      噪音       │    提取纯文本内容
└────────┬────────┘
         ▼
┌─────────────────┐
│ Step 3: 语言检测  │  ← 检测主要语言，过滤非目标语言样本
└────────┬────────┘
         ▼
┌─────────────────┐
│ Step 4: 去重     │  ← 精确去重 + 模糊去重(MinHash/LSH)
└────────┬────────┘
         ▼
┌─────────────────┐
│ Step 5: 质量过滤  │  ← 长度过滤、困惑度过滤、垃圾文本过滤
└────────┬────────┘
         ▼
┌─────────────────┐
│ Step 6: PII 移除 │  ← 敏感信息检测与脱敏
└────────┬────────┘
         ▼
┌─────────────────┐
│ Step 7: 格式检查  │  ← 完整性校验、标签一致性检查
└────────┬────────┘
         ▼
   清洗完成数据
```

### 3.2 去重策略

| 去重方式 | 方法 | 适用场景 | 优缺点 |
|---------|------|---------|-------|
| 精确去重 | MD5/SHA256 哈希 | 完全重复文本 | 简单高效，但无法检测近似重复 |
| 模糊去重 | MinHash + LSH | 近似重复、文档间相似 | 可发现部分重叠文档，参数调优复杂 |
| 行级去重 | 逐行计算哈希 | 代码数据集 | 避免重复代码片段 |
| N-gram 去重 | 计算 N-gram 重叠度 | 长文档 | 细粒度，计算量大 |
| Embedding 去重 | 向量相似度 > 阈值 | 语义重复 | 效果好，成本高 |

### 3.3 代码数据清洗

代码数据相比自然语言数据有特殊的清洗要求：

```python
# code_cleaning.py — 代码数据集清洗示例
import re
import json
from typing import List, Dict

def clean_code_sample(sample: Dict) -> Dict:
    """清洗单条代码样本"""
    content = sample.get("content", "")

    # 1. 移除 BOM 头
    content = content.lstrip("﻿")

    # 2. 统一换行符
    content = content.replace("\r\n", "\n").replace("\r", "\n")

    # 3. 移除不可见字符（保留换行和缩进）
    content = "".join(c for c in content if c.isprintable() or c in "\n\t ")

    # 4. 压缩多余空行（最多保留 2 个连续空行）
    content = re.sub(r"\n{3,}", "\n\n", content)

    # 5. 移除只有注释/空格的无效行
    lines = content.split("\n")
    cleaned_lines = []
    for line in lines:
        stripped = line.strip()
        if stripped.startswith("//") or stripped.startswith("#"):
            continue  # 纯注释行可以考虑移除
        cleaned_lines.append(line)
    content = "\n".join(cleaned_lines)

    # 6. 检测是否可编译/解析
    sample["cleaned_content"] = content
    return sample

def filter_code_samples(samples: List[Dict]) -> List[Dict]:
    """过滤低质量代码样本"""
    filtered = []
    for sample in samples:
        content = sample.get("content", "")
        lang = sample.get("language", "")

        # 代码太短 → 跳过
        if len(content) < 50:
            continue

        # 语言未知 → 尝试检测
        if not lang:
            continue

        # 包含过长的行 → 可能是混淆代码
        if any(len(line) > 500 for line in content.split("\n")):
            continue

        # 注释占比过高 → 可能是文档而不是代码
        lines = content.split("\n")
        comment_lines = sum(1 for l in lines if l.strip().startswith(("//", "#", "/*", "*", "--")))
        if len(lines) > 0 and comment_lines / len(lines) > 0.7:
            continue

        filtered.append(sample)
    return filtered
```

## 4. 标注标准与流程

### 4.1 标注质量控制的五个维度

```
标注质量控制
│
├── 1. 一致性 (Consistency)
│   ├── 同一标注者在不同时间的一致性
│   ├── 不同标注者之间的一致性
│   └── 方式：定期进行一致性测试，计算 Cohen's Kappa
│
├── 2. 准确性 (Accuracy)
│   ├── 标注结果反映真实情况的准确程度
│   └── 方式：专家抽检，黄金标准集比对
│
├── 3. 覆盖度 (Coverage)
│   ├── 标注样本对目标分布的覆盖程度
│   └── 方式：统计各类型样本比例，确保分布均衡
│
├── 4. 清晰度 (Clarity)
│   ├── 标注指南的清晰无歧义程度
│   └── 方式：标注前测试指南，收集标注者反馈
│
└── 5. 效率 (Efficiency)
    ├── 单位时间的标注量
    └── 方式：优化流程，使用工具辅助
```

### 4.2 指令微调标注规范

```yaml
# annotation_guidelines.yaml — 指令标注规范示例
annotation_rules:
  instruction:
    - 指令应该清晰明确，不需要额外解释
    - 指令应该包含足够上下文
    - 指令应该指定输出格式（如果需要特定格式）
    - 避免模糊表达："帮我处理这个" → "请为这个 Python 函数添加类型注解"

  response:
    - 代码输出必须提供完整可运行的版本（除非指令要求片段）

    - 过于简短且没有实质内容（如仅"Yes"）

  format_requirements:
    code: |
      使用 ```language 代码块包裹
      代码前先简要描述思路
      必要时附上运行示例

```

### 4.3 标注者一致性评估

计算标注者之间的一致性：

```python
# inter_annotator_agreement.py
from sklearn.metrics import cohen_kappa_score
import numpy as np

def calculate_kappa(annotator_a: list, annotator_b: list) -> float:
    """计算 Cohen's Kappa 系数"""
    return cohen_kappa_score(annotator_a, annotator_b)

def calculate_agreement_rate(annotator_a: list, annotator_b: list) -> float:
    """计算简单一致率"""
    agreements = sum(1 for a, b in zip(annotator_a, annotator_b) if a == b)
    return agreements / len(annotator_a)

def flag_low_agreement_samples(
    annotations: dict,
    threshold: float = 0.6
) -> list:
    """标记一致性低于阈值的样本"""
    # annotations: {sample_id: {annotator_id: label}}
    flagged = []
    for sample_id, annotators in annotations.items():
        labels = list(annotators.values())
        # 计算两两一致率
        agreements = []
        for i in range(len(labels)):
            for j in range(i + 1, len(labels)):
                agreements.append(1 if labels[i] == labels[j] else 0)
        agreement_rate = np.mean(agreements) if agreements else 1.0
        if agreement_rate < threshold:
            flagged.append((sample_id, agreement_rate))
    return flagged
```

## 5. 评测体系

### 5.1 三类评测

| 评测类型 | 频率 | 执行方式 | 作用 |
|---------|------|---------|------|
| 自动评测 | 每次训练/微调后 | 脚本批量运行 | 快速反馈、回归检测 |
| 人工评测 | 每周/每版本 | 标注员打分 | 捕捉自动评测无法覆盖的方面 |
| 回归评测 | 每次提交 | 自动化 pipeline | 确保新版本不劣于旧版本 |

### 5.2 自动评测指标

#### 文本生成质量指标

| 指标 | 测量内容 | 范围 | 适用场景 | 局限性 |
|-----|---------|------|---------|-------|
| BLEU | N-gram 精确匹配 | [0, 1] | 机器翻译、摘要 | 对词汇变化不敏感 |
| ROUGE-L | 最长公共子序列 | [0, 1] | 摘要生成 | 忽略语法正确性 |
| ROUGE-1/2 | Unigram/Bigram 召回 | [0, 1] | 摘要评估 | 简单 N-gram 匹配 |
| METEOR | 同义词+词干匹配 | [0, 1] | 翻译评估 | 需要同义词表 |
| Perplexity | 模型对文本的困惑度 | [1, +∞) | 语言模型质量 | 偏向短文本 |
| BERTScore | BERT 向量余弦相似 | [-1, 1] | 语义相似度 | 需要 GPU |

#### 代码生成指标

| 指标 | 测量内容 | 实现方式 |
|-----|---------|---------|
| Pass@k | 前 k 次生成中有成功次数比例 | 单元测试验证 |
| 编译成功率 | 代码能通过编译的比例 | 编译器/解释器验证 |
| 精确匹配 (EM) | 与参考答案完全一致的比例 | 字符串匹配 |
| 代码复杂度 | 生成代码的圈复杂度 | 静态分析工具 |
| 测试覆盖率 | 生成代码的单元测试覆盖 | coverage 工具 |
| 健壮性 | 对异常输入的处理能力 | 注入错误输入测试 |

### 5.3 BLEU 计算示例

```python
# bleu_evaluation.py — BLEU 评分计算
from collections import Counter
import math

def ngrams(tokens: list, n: int):
    """生成 N-gram"""
    return [tuple(tokens[i:i+n]) for i in range(len(tokens) - n + 1)]

def modified_precision(reference: list, candidate: list, n: int):
    """计算修正精确率"""
    ref_ngrams = Counter(ngrams(reference, n))
    cand_ngrams = Counter(ngrams(candidate, n))

    matches = 0
    total = 0
    for ngram, count in cand_ngrams.items():
        total += count
        matches += min(count, ref_ngrams.get(ngram, 0))

    return matches / total if total > 0 else 0

def bleu_score(reference: str, candidate: str, max_n: int = 4) -> float:
    """计算 BLEU 分数"""
    ref_tokens = reference.split()
    cand_tokens = candidate.split()

    # 简短惩罚
    if len(cand_tokens) <= len(ref_tokens):
        brevity_penalty = math.exp(1 - len(ref_tokens) / len(cand_tokens)) if len(cand_tokens) > 0 else 0
    else:
        brevity_penalty = 1.0

    # 计算各 N-gram 精确率
    precisions = []
    for n in range(1, max_n + 1):
        p = modified_precision(ref_tokens, cand_tokens, n)
        precisions.append(p if p > 0 else 1e-10)

    # 几何平均 + 指数权重
    avg_precision = sum(math.log(p) for p in precisions) / max_n
    bleu = brevity_penalty * math.exp(avg_precision)
    return bleu
```

## 6. 数据增强

### 6.1 数据增强策略

| 策略 | 方法 | 适用场景 | 注意事项 |
|-----|------|---------|---------|
| 回译 (Back Translation) | 翻译到中间语言再译回 | 文本分类、QA | 可能引入翻译误差 |
| EDA (Easy Data Augmentation) | 分词替换、随机插入等 | 短文本 | 简单但效果有限 |
| 代码 mask | 随机 mask 代码片段并让模型补全 | 代码模型 | 需要保持语法有效 |
| 指令改写 | 用 LLM 改写而保留意图 | 指令微调 | 需要控制多样性 |
| 模板填充 | 使用预定义模板插入变量 | 结构化数据 | 需要精心设计模板 |
| 对抗样本 | 添加微小扰动 | 鲁棒性测试 | 需确保标签不变 |

### 6.2 指令改写增强

```python
# instruction_augmentation.py
def augment_with_paraphrase(instruction: str, response: str, model="gpt-4") -> tuple:
    """使用 LLM 改写指令，保持意图"""
    prompt = f"""请将以下指令改写成 3 个不同的版本，保持原意图不变，
但改变表述方式、句式结构或具体场景。

原始指令：{instruction}

请以 JSON 数组格式输出：["改写1", "改写2", "改写3"]"""

    # 调用 LLM 获取改写
    import json
    import openai

    resp = openai.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        temperature=0.7
    )

    try:
        augmented = json.loads(resp.choices[0].message.content)
        return [(inst, response) for inst in augmented]
    except:
        return [(instruction, response)]
```

## 7. 对 Frees Agent 用户最实用的建议

### 7.1 优先级排序

```
第一优先 ── 你自己的数据
├── 你真实写过的代码（工作/开源项目）
├── 你真实问过的问题（工具使用、调试记录）
├── 你在项目中反复使用的工作流
└── 你希望模型遵守的输出风格示例

第二优先 ── 高质量公开数据
├── 领域相关的论文/文章
├── 行业标准数据集
└── 代码竞赛/开源项目精选

第三优先 ── 合成数据
├── Self-Instruct 生成的领域指令
├── 从文档自动生成的 QA 对
└── 模板填充的结构化数据
```

### 7.2 最小可行数据集策略

如果你刚开始构建数据集，按这个顺序逐步建立：

1. **收集 100 条** 你实际场景中的真实数据
2. **人工标注** 这 100 条，确保质量
3. **训练第一个基线模型**，确认流程没问题
4. **扩展到 1000 条**，包含更多多样性
5. **评估模型在真实场景的表现**，找出弱点
6. **针对性补充** 模型表现差的场景数据
7. **重复步骤 5-6** 进行迭代优化

### 7.3 常见陷阱

| 陷阱 | 表现 | 解决方法 |
|-----|------|---------|
| 数据泄漏 | 评测数据包含训练数据 | 严格切分 train/dev/test |
| 标注泄漏 | 标注者参考了模型输出 | 盲标，AB 实验 |
| 分布偏移 | 训练数据与真实场景不一致 | 持续收集真实场景数据 |
| 过度去重 | 去掉了有价值的变化 | 使用基于语义的去重而非精确去重 |
| 忽视样本平衡 | 长尾场景被淹没 | 分层采样，类别加权 |
| 过度清洗 | 去掉了有价值的边缘案例 | 保留困难样本，单独标注 |
