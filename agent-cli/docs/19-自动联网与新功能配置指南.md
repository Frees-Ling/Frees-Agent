# 自动联网与新功能配置指南

本文档详细说明 Frees Agent 高级功能的配置原理和方法，包括自动联网检索、模型自动回退、跨设备记忆同步、对话压缩与 Token 预算控制、规划层与反思层、MCP 工具系统、向量记忆与任务记忆等能力。

---

## 1. 配置系统概述

### 1.1 配置文件位置

Frees Agent 按以下优先级加载配置（高优先级覆盖低优先级）：

1. **项目配置**：`.frees-agent/config.json`（项目根目录）
2. **全局配置**：`~/.frees-agent/config.json`（用户目录）
3. **默认配置**：代码内置默认值

### 1.2 配置合并规则

使用深度合并（deep merge），用户配置只覆盖指定的字段。环境变量可以通过 `${MY_VAR}` 语法引用。

### 1.3 配置段总览

| 配置段 | 功能 | 难度 |
|--------|------|------|
| `defaultProvider` | 默认模型 Provider | 入门 |
| `providers` | 各 Provider 连接配置 | 入门 |
| `mcpServers` | MCP 外部服务器配置 | 进阶 |
| `memory` | 记忆系统配置 | 进阶 |
| `conversation` | 对话行为配置 | 入门 |
| `tools` | 工具配置 | 入门 |
| `roles` | 角色模型配置（规划器、评论家） | 进阶 |

## 2. 自动联网搜索（Tavily）

### 2.1 工作原理

Frees Agent 集成了 Tavily Search API 作为联网搜索后端。当用户的问题包含时效性关键词时，Agent 自动发起联网检索。

```
用户提问："最近 AI Agent 框架有什么新进展？"
    │
    ▼
关键词检测 → "最近"命中 → 触发搜索
    │
    ▼
构建搜索 query → 调用 Tavily MCP 工具
    │
    ▼
返回结构化结果（标题+摘要+URL）
    │
    ▼
结果注入 LLM 上下文 → 生成基于搜索的回答
```

### 2.2 配置步骤

**第一步：获取 Tavily API Key**

访问 https://tavily.com 注册并创建 API Key：

```bash
export TAVILY_API_KEY="your-tavily-api-key"
```

**第二步：配置 MCP 服务**

Tavily 通过 MCP 协议集成：

```json
{
  "mcpServers": {
    "tavily": {
      "command": "npx",
      "args": ["@tavily/mcp"],
      "env": {
        "TAVILY_API_KEY": "${TAVILY_API_KEY}"
      }
    }
  },
  "tools": {
    "webSearch": {
      "enabled": true,
      "provider": "tavily",
      "maxResults": 5
    }
  }
}
```

### 2.3 自动触发机制

系统通过以下规则判断是否需要联网搜索：

```js
function shouldAutoSearch(query) {
  const patterns = [
    /最新/, /今天/, /最近/, /新闻/i,
    /news/i, /latest/i, /trending/i,
    /update/i, /202[4-9]/, /[昨今明]天/,
  ];
  return patterns.some(p => p.test(query));
}
```

### 2.4 Tavily vs 传统搜索

| 特性 | Tavily | 传统搜索引擎 API |
|------|--------|-----------------|
| 返回格式 | AI 友好的结构化 JSON | 原始 HTML/XML |
| 内容摘要 | 已提取的关键信息 | 仅有 snippet |
| 相关性评分 | 内置 AI 评分 | 无 |
| 定制化 | 搜索引擎、时间范围 | 有限 |

Tavily 的 AI 预处理层使得搜索结果可以直接注入 LLM 上下文：

```json
{
  "results": [{
    "title": "AI Agent 框架 2026 趋势",
    "url": "https://example.com",
    "content": "2026 年 AI Agent 框架呈现...",
    "score": 0.95
  }]
}
```

## 3. 网页内容抓取（Web Fetch）

### 3.1 与 Tavily 的互补

- **Tavily**：搜索"有什么相关网页"
- **Web Fetch**：抓取"这个网页写了什么"

### 3.2 配置

```json
{
  "tools": {
    "webFetch": {
      "enabled": true,
      "maxContentLength": 10000
    }
  }
}
```

### 3.3 技术实现

```
Node.js http(s).get → 获取原始 HTML
    → HTML → Markdown 转换
    → 提取主要文本（去除导航/广告）
    → 截取合理长度
    → 返回给 LLM
```

### 3.4 Tavily + Web Fetch 配合流程

```
用户：我想了解 AutoGPT 的最新进展

Agent 内部流程：
1. 检测"最新" → 触发 Tavily 搜索
2. Tavily 返回 5 个搜索结果摘要
3. Agent 判断最有价值的结果
4. 调用 web_fetch 抓取最佳结果的完整内容
5. 综合搜索摘要+抓取内容，生成完整回答
```

## 4. MCP 工具系统

### 4.1 MCP 协议简介

MCP（Model Context Protocol）是 Anthropic 提出的开源标准协议，定义 LLM 应用与外部工具之间的通信规范。Frees Agent 使用 MCP 作为工具扩展的统一接口。

```
┌────────────────┐     JSON-RPC 2.0    ┌────────────────┐
│  Frees Agent   │ ◄── stdin/stdout ──► │  MCP Server    │
│  (MCP Client)  │                      │  (tavily, fs)  │
└────────────────┘                      └────────────────┘
```

### 4.2 MCP 架构在 Frees Agent 中的位置

```
Frees Agent
    │
    ├── 内置工具层
    │   ├── read_file / write_file / replace_in_file
    │   ├── bash / shell
    │   ├── web_fetch
    │   └── git_*
    │
    └── MCP 扩展层
        ├── @tavily/mcp                    → 联网搜索
        ├── @anthropic/mcp-server-fs       → 文件系统
        ├── @anthropic/mcp-server-puppeteer → 网页截图
        ├── @anthropic/mcp-server-ffmpeg   → 视频处理
        └── @anthropic/mcp-server-pillow   → 图片处理
```

### 4.3 配置格式

```json
{
  "mcpServers": {
    "<server-name>": {
      "command": "npx",
      "args": ["<package-name>"],
      "env": { "API_KEY": "${ENV_VAR}" }
    }
  }
}
```

### 4.4 推荐的 MCP 服务器

| MCP 服务器 | 能力 | 命令 | 依赖 |
|------------|------|------|------|
| `@tavily/mcp` | 联网搜索 | `npx @tavily/mcp` | TAVILY_API_KEY |
| `@anthropic/mcp-server-fs` | 文件系统 | `npx @anthropic/mcp-server-fs /dir` | 无 |
| `@anthropic/mcp-server-puppeteer` | 网页截图 | `npx @anthropic/mcp-server-puppeteer` | Chromium |
| `@anthropic/mcp-server-ffmpeg` | 音视频处理 | `npx @anthropic/mcp-server-ffmpeg` | FFmpeg |
| `@anthropic/mcp-server-pillow` | 图片处理 | `npx @anthropic/mcp-server-pillow` | Python + Pillow |

### 4.5 MCP 连接生命周期

```
启动 Frees Agent
    │
    ▼
读取 mcpServers 配置
    │
    ▼
为每个 server 调用 getOrConnect()
    │
    ├── spawn 子进程
    ├── 发送 initialize (JSON-RPC)
    ├── 接收 capabilities
    ├── 发送 notifications/initialized
    └── 进入消息循环
    │
    ▼
调用 listAllTools() → 获取工具列表
    │
    ▼
LLM 决定调用 → callTool(server, tool, args) → 返回结果
```

### 4.6 安全注意事项

- MCP Server 拥有与 Frees Agent 相同的系统权限
- 不要从不可信来源运行 MCP Server
- 敏感工具（如 fs、shell）应谨慎授权
- `allowShellInChat = false` 时，Agent 无法在聊天中调用 shell

## 5. 模型自动回退（Auto Provider Fallback）

### 5.1 为什么需要自动回退？

- Ollama 服务未启动
- 本地模型加载失败
- LM Studio 端口冲突
- 本地模型回答质量不足

### 5.2 配置

```json
{
  "conversation": {
    "autoProviderFallback": true
  }
}
```

### 5.3 回退流程

```
请求 LLM
    │
    ▼
尝试 ollama ─── 成功 → 返回
    │
    失败
    ▼
尝试 openai-compatible ─── 成功 → 返回
    │
    失败
    ▼
尝试 mcp ─── 成功 → 返回
    │
    失败
    ▼
尝试 anthropic ─── 成功 → 返回
    │
    失败 → 报错
```

### 5.4 探活机制

系统启动时逐一检查每个 provider 的可用性：

```js
async function checkProviderHealth(provider) {
  try {
    const response = await fetch(provider.baseUrl, {
      method: 'HEAD',
      signal: AbortSignal.timeout(5000)
    });
    return { alive: response.ok, latency: Date.now() - start };
  } catch {
    return { alive: false, latency: Infinity };
  }
}
```

### 5.5 Provider 优先级

| Provider | 优先级 | 说明 |
|----------|--------|------|
| `ollama` | 1（最高） | 本地，延迟最低 |
| `openai-compatible` | 2 | 本地，适合大模型 |
| `mcp` | 3 | 通过 MCP 调用 |
| `anthropic` | 4（最低） | 云端，质量最高 |

### 5.6 命令行控制

```bash
frees-agent chat . --auto-provider     # 启用
frees-agent chat . --no-auto-provider  # 禁用
```

## 6. 跨设备记忆合并

### 6.1 使用场景

现代开发者通常在多台设备上工作（办公室台式机、家用笔记本、远程服务器）。跨设备合并确保无论在哪台设备上对话，Agent 都认识你。

### 6.2 配置

```json
{
  "memory": {
    "autoMergeAcrossDevices": true,
    "syncRoots": ["/path/to/shared/directory"],
    "syncWritesToRoots": false
  }
}
```

`syncRoots` 指向所有设备都能访问的共享目录：

| 共享方案 | 示例路径 | 特点 |
|----------|---------|------|
| iCloud Drive | `~/Library/Mobile Documents/com~apple~CloudDocs/` | 苹果设备间无缝 |
| Syncthing | `/path/to/sync/` | 跨平台 P2P |
| NAS 挂载 | `/Volumes/nas/` | 局域网稳定 |
| Git 仓库 | 本地 + git push/pull | 手动但有版本历史 |

### 6.3 合并策略

**Profile（用户画像）**：
- 字段级合并，每个字段独立比较
- 数组类型做并集去重
- 标量类型以最新时间戳为准

**Durable Memory（长期记忆）**：
- 以 `category + content` 为唯一键去重

**Session（会话）**：
- 所有消息按时间戳排序
- 完全相同的内容去重
- 对话摘要做拼接

### 6.4 写入策略

- **仅本地写入**（推荐 `syncWritesToRoots = false`）：只在当前设备写入，读取时合并
- **全量同步**（`syncWritesToRoots = true`）：每次写入同时写入所有 syncRoots

### 6.5 手动操作

```bash
frees-agent memory merge    # 手动触发合并
frees-agent memory stats    # 查看记忆状态
```

## 7. 对话压缩与 Token 预算控制

### 7.1 问题背景

LLM 的上下文窗口有限。小型本地模型可能只有 4K-8K。不控制的话，对话历史会逐渐膨胀。

### 7.2 三层压缩防线

```
对话消息累积
    │
    ▼
第一层：消息条数限制 (maxHistoryMessages: 10)
    │  → 只保留最近 N 条原始消息
    │
    ▼
第二层：最近消息 token 预算 (maxRecentContextTokens: 2800)
    │  → 减少保留的原始消息条数
    │
    ▼
第三层：历史总硬上限 (hardContextCap: 3200)
    │  → 强制截断，丢弃最早历史
    │
    ▼
最终上下文（摘要 + 最近消息 + 检索记忆）
```

### 7.3 全部参数详解

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxOutputTokens` | 16000 | 单次回答最大 token 数 |
| `keepRecentMessages` | 12 | 保留的最近原始消息条数 |
| `summarizeAfterMessages` | 18 | 超过此条数触发摘要压缩 |
| `maxRecentContextTokens` | 2800 | 最近消息 token 预算上限 |
| `maxHistoryMessages` | 10 | 发送给模型的历史消息最大条数 |
| `hardContextCap` | 3200 | 全部历史上下文的 token 硬上限 |
| `autoContinueOnCutoff` | true | 回答被截断时自动续写 |

### 7.4 针对不同模型的配置建议

| 模型 | 窗口 | `hardContextCap` | 说明 |
|------|------|-----------------|------|
| qwen2.5-coder:1.5b | 32K | 2000 | 小模型严格限制 |
| qwen2.5-coder:7b | 128K | 3200 | 推荐配置 |
| qwen3.5-14b | 128K | 6000 | 中等配置 |
| claude-3-5-sonnet | 200K | 16000 | 大窗口可放宽 |

### 7.5 Token 预算链

```
systemPrompt (含记忆注入)       → 约 500-1500 tokens
prompt (含工作区+Skill+联网)    → 可变
history (含最近的对话轮次)      → 按预算裁剪
                              ↓
有效上下文 ≈ maxRecentContextTokens
硬上限: hardContextCap
```

### 7.6 历史消息裁剪算法

```js
function trimHistoryByBudget(history, budget) {
  // 1. 从最新消息开始往回取
  // 2. 单条超预算则截取尾部
  // 3. 总预算超限按 0.7 比例缩减
  // 4. 移除开头的 assistant 消息
}
```

### 7.7 安全保护机制

- **空内容过滤**：自动过滤空或异常的 assistant 历史消息，避免 API 报错
- **空回复保护**：空回复不会写入长期记忆
- **Qwen3 兼容**：自动附带 `enable_thinking=false`

## 8. 规划层与反思层

### 8.1 规划层 (Planner)

在回答复杂问题前先生成结构化执行计划：

```json
{
  "conversation": { "planningEnabled": true }
}
```

**工作流程**：

```
用户："帮我写一个 Node.js CLI 工具"
    │
    ▼
Planner 生成规划：
1. 分析需求
2. 设计架构
3. 实现主入口
4. 实现核心功能
5. 添加测试
6. 验证
    │
    ▼
按规划逐步执行
```

### 8.2 反思层 (Critic)

回答完成后进行自检和修正：

```json
{
  "conversation": { "reflectionEnabled": true }
}
```

**检查维度**：
- 回答是否完整覆盖问题？
- 是否有事实性错误？
- 代码是否可以运行？
- 是否有更好的解决方案？

### 8.3 独立角色模型配置

```json
{
  "roles": {
    "planner": {
      "provider": "openai-compatible",
      "model": "qwen/qwen3.5-14b"
    },
    "critic": {
      "provider": "",
      "model": ""
    }
  }
}
```

当 `provider` 为空时使用 `defaultProvider`。这种设计允许：
- 用小模型做快速规划
- 用强模型做深度反思

## 9. 向量记忆与任务记忆

### 9.1 向量记忆

通过文本向量化实现语义检索：

```json
{
  "memory": {
    "vectorMemory": {
      "enabled": true,
      "topK": 6
    }
  }
}
```

**存储文件**：`memory/vector-memories.json`

**工作原理**：

```
每轮对话后 → ingest.js 提取关键信息
    → vector.js embedText() → 256 维 FNV-1a 向量
    → 存储到 vector-memories.json

新问题时 → queryVectorMemories(query, topK)
    → 查询向量化
    → 余弦相似度排序
    → 过滤（阈值 > 0.06）
    → 返回 top-K 相关记忆
```

### 9.2 任务记忆

跟踪长期待办事项和任务状态，自动启用，无需额外配置。

**存储文件**：`memory/task-memory.json`

**状态机**：

```
pending → in_progress → completed
                    → blocked → pending (重激活)
```

**任务记忆合并**：

```js
export function loadAndMergeTasks(config) {
  const globalTasks = loadTasks(config.globalPath);
  const localTasks = loadTasks(config.localPath);
  return mergeTasks(globalTasks, localTasks);
}
```

## 11. 故障排查

| 症状 | 可能原因 | 解决方案 |
|------|---------|----------|
| 联网搜索不工作 | TAVILY_API_KEY 未设置 | 检查 `env \| grep TAVILY` |
| 模型回退失败 | 所有 provider 不可用 | 检查各服务 URL 和端口 |
| 记忆不合并 | syncRoots 路径不正确 | 确认目录存在且可读 |
| Token 超限 | hardContextCap 过高 | 降低到模型窗口的 70% 以内 |
| 对话一直截断 | maxOutputTokens 太小 | 增大或开启 autoContinueOnCutoff |
| Qwen3 只输出思考过程 | 未设置兼容模式 | 升级到 v2.0+ |

### 调试命令

```bash
frees-agent doctor        # 系统诊断
frees-agent config        # 查看当前配置
frees-agent cost          # Token 用量统计
frees-agent compact       # 手动压缩
```
