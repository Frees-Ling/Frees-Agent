# 系统权限、电脑控制与安全边界

## 1. 先说最重要的事

`Frees Agent` 不应该偷偷获得系统权限。安全是所有 Agent 能力的基石，必须在设计之初就建立清晰的安全边界。

### 1.1 核心安全原则

```
安全原则体系
│
├── 1. 默认最小权限 (Principle of Least Privilege)
│   ├── 只授予完成任务所需的最小权限
│   ├── 能读不写，能写不执行
│   └── 能不提权就不提权
│
├── 2. 明确告知 (Informed Consent)
│   ├── 每次提权都要有明确的用户确认
│   ├── 告知权限的具体范围和影响
│   └── 告知可能的风险
│
├── 3. 明确范围 (Scoped Access)
│   ├── 权限绑定到特定目录/文件/操作
│   ├── 权限有失效时间
│   └── 可追溯到具体会话
│
├── 4. 完整审计 (Audit Trail)
│   ├── 所有高风险操作记录日志
│   ├── 日志不可篡改
│   └── 支持事后溯源
│
└── 5. 可撤销 (Revocable)
    ├── 用户随时可以撤销授权
    ├── 权限变更立即生效
    └── 提供可视化的权限管理界面
```

### 1.2 安全威胁模型

```
威胁来源
│
├── 来自模型的威胁
│   ├── Prompt 注入：恶意指令注入到模型输入
│   ├── 间接提示注入：通过读取的文件内容注入指令
│   ├── 工具误用：模型调用了错误的工具或参数
│   └── 幻觉操作：模型凭空创造了不存在的操作
│
├── 来自外部的威胁
│   ├── 网络攻击：API 端点被攻击
│   ├── 中间人攻击：网络通信被拦截
│   ├── 恶意插件：第三方插件引入风险
│   └── 供应链攻击：依赖库被植入恶意代码
│
└── 来自用户的威胁
    ├── 误操作：用户授权了不应该授权的操作
    ├── 社会工程：用户被诱导执行危险操作
    └── 权限滥用：具有高级权限的被滥用
```

## 2. 权限分级体系

### 2.1 Frees Agent 权限等级

```
等级 0: 无权限（纯对话）
├── 仅文本对话
├── 无文件访问
├── 无命令执行
└── 无网络访问

等级 1: 只读权限
├── 读取指定目录的文件
├── 搜索文本
├── 查看文件列表
├── 读取 Git 状态
└── 不允许写文件或执行命令

等级 2: 写入权限
├── 等级 1 所有权限
├── 写入指定目录的文件
├── 创建/修改/删除文件
├── 文件编辑操作
└── 不允许执行系统命令

等级 3: 受限执行权限
├── 等级 2 所有权限
├── 执行白名单命令
├── 运行脚本
├── 构建和测试
└── 不允许任意命令执行

等级 4: 完全执行权限
├── 等级 3 所有权限
├── 执行任意系统命令
├── 控制外部应用
├── 网络访问
└── 需要明确用户确认每次高风险操作

等级 5: 管理员权限
├── 等级 4 所有权限
├── 修改系统配置
├── 安装/卸载软件
├── 访问所有系统资源
└── 仅限受信任的用户和场景
```

      - pattern: "go (build|test|mod)"

        description: "危险：提权操作"
      - pattern: "chmod 777*"
        description: "危险：修改文件权限"

      - pattern: ":(){ :|:& };:"

    allow_domains:
      - "api.github.com"

  log_path: "${workspace}/.frees-agent/audit.log"

### 3.2 Prompt 注入防护

```javascript
// prompt_injection_guard.js — Prompt 注入检测
class PromptInjectionGuard {
  constructor() {
    this.suspicious_patterns = [
      /ignore\s+(all\s+)?previous\s+instructions/i,
      /ignore\s+everything\s+(above|below|before)/i,
      /you\s+are\s+(now|not)\s+/i,
      /forget\s+(all\s+)?(previous|prior)\s+/i,
      /system\s+(prompt|instruction|message)/i,
      /role\s*[:=]\s*(system|assistant)/i,
      /<\s*system\s*>.*?<\s*\/\s*system\s*>/is,
      /do\s+not\s+(follow|obey|listen)/i,
      /print\s+(your\s+)?(system\s+)?prompt/i,
    ];

    this.base64_pattern = /[A-Za-z0-9+/]{40,}={0,2}/;
  }

  checkUserInput(text) {
    const warnings = [];

    // 检查可疑模式
    for (const pattern of this.suspicious_patterns) {
      if (pattern.test(text)) {
        warnings.push({
          type: 'prompt_injection',
          pattern: pattern.source,
          severity: 'high',
          match: text.match(pattern)?.[0]
        });
      }
    }

    // 检查 Base64 编码（编码的注入指令）
    if (this.base64_pattern.test(text)) {
      try {
        const decoded = Buffer.from(text.match(this.base64_pattern)[0], 'base64').toString();
        if (this.suspicious_patterns.some(p => p.test(decoded))) {
          warnings.push({
            type: 'encoded_injection',
            severity: 'high',
            detail: 'Base64 编码包含可疑内容'
          });
        }
      } catch {
        // 不是有效 Base64，忽略
      }
    }

    return {
      safe: warnings.length === 0,
      warnings,
      risk_level: warnings.some(w => w.severity === 'high') ? 'high' : 'low'
    };
  }

  checkFileContent(filename, content) {
    // 检查文件内容中的间接注入
    if (filename.endsWith('.md') || filename.endsWith('.txt')) {
      return this.checkUserInput(content);
    }
    return { safe: true, warnings: [] };
  }
}
```

### 4.2 Shell 执行安全校验

Frees Agent 内置的危险命令拦截机制：

```javascript
// shell_security.js — Shell 安全校验（源码简化）
const DANGEROUS_PATTERNS = [
  // 递归删除
  { pattern: /\brm\s+(-rf|--recursive)\s+\/\s*/i, reason: '递归删除根目录' },
  { pattern: /\brm\s+(-rf|--recursive)\s+(~|\/home|\/Users)\s*/i, reason: '递归删除用户目录' },

  // 提权
  { pattern: /\bsudo\s+/i, reason: 'Sudo 提权' },
  { pattern: /\bsu\s+/i, reason: '切换用户' },
  { pattern: /\bchown\s+/i, reason: '修改文件所有者' },

  // 危险权限
  { pattern: /\bchmod\s+777\s+/i, reason: '设置文件为完全可执行' },
  { pattern: /\bchmod\s+-R\s+777\s+/i, reason: '递归设置完全权限' },

  // 设备操作
  { pattern: /(>|\|)\s*\/dev\/(null|zero|random|urandom)/i, reason: '覆写设备文件' },
  { pattern: /\bdd\s+/i, reason: '低级磁盘操作' },
  { pattern: /\bmkfs/i, reason: '格式化文件系统' },

  // fork 炸弹等 DoS
  { pattern: /:\(\s*\)\s*\{/, reason: 'Fork 炸弹' },

  // 网络攻击
  { pattern: /\bnmap\s+/i, reason: '端口扫描' },
  { pattern: /\bnikto\s+/i, reason: 'Web 漏洞扫描' },

  // 危险管道
  { pattern: /\bcurl\s+.*\|\s*(bash|sh|zsh)/i, reason: '直接执行远程脚本' },
  { pattern: /\bwget\s+.*\|\s*(bash|sh|zsh)/i, reason: '直接执行远程脚本' },
];

function validateShellCommand(command) {
  const violations = [];
  for (const { pattern, reason } of DANGEROUS_PATTERNS) {
    if (pattern.test(command)) {
      violations.push({ command, pattern: pattern.source, reason });
    }
  }
  return {
    safe: violations.length === 0,
    violations
  };
}
```

## 5. 文件系统访问控制

### 5.1 路径安全

```javascript
// path_security.js — 路径安全控制
const path = require('path');

class PathSecurity {
  constructor(allowedBasePaths) {
    this.allowedBasePaths = allowedBasePaths.map(p => path.resolve(p));
  }

  /**
   * 验证路径是否在允许范围内
   * 防止路径遍历攻击 (../ etc.)
   */
  validatePath(targetPath) {
    const resolved = path.resolve(targetPath);

    // 检查是否在允许的基路径内
    const allowed = this.allowedBasePaths.some(base =>
      resolved === base || resolved.startsWith(base + path.sep)
    );

    if (!allowed) {
      return {
        ok: false,
        error: `路径 ${resolved} 不在允许范围内`,
        allowed: this.allowedBasePaths
      };
    }

    return { ok: true, resolved };
  }

  /**
   * 敏感文件检测
   */
  isSensitiveFile(filename) {
    const sensitivePatterns = [
      /\.env$/,
      /\.env\./,
      /credentials/i,
      /\.ssh\//,
      /id_rsa/,
      /\.pem$/,
      /\.key$/,
      /password/i,
      /secret/i,
      /token/i,
      /\.git\/config$/,
      /config\.json$/  // 可能包含密钥
    ];

    return sensitivePatterns.some(p => p.test(filename));
  }

  /**
   * 获取文件的推荐处理方式
   */
  getFileAccessLevel(filename) {
    if (this.isSensitiveFile(filename)) {
      return {
        read: false,
        write: false,
        reason: '敏感文件，禁止访问'
      };
    }

    const ext = path.extname(filename).toLowerCase();
    const binaryExtensions = ['.exe', '.dll', '.so', '.dylib', '.bin', '.dat', '.db'];
    const isBinary = binaryExtensions.includes(ext);

    return {
      read: !isBinary,
      write: !isBinary,
      reason: isBinary ? '二进制文件，仅支持文本文件' : '允许访问'
    };
  }
}
```

### 5.2 敏感文件列表

| 文件/目录 | 风险等级 | 处理方式 |
|-----------|---------|---------|
| `.env` | 高危 | 禁止读写 |
| `.env.*` | 高危 | 禁止读写 |
| `credentials.*` | 高危 | 禁止读写 |
| `~/.ssh/id_rsa` | 高危 | 禁止读写 |
| `*.pem` | 高危 | 禁止读写 |
| `**/node_modules/**` | 低危 | 可读，禁止写入 |
| `**/.git/**` | 中危 | 可读状态，禁止修改 |
| `package-lock.json` | 低危 | 可读，谨慎写入 |
| `.frees-agent/*` | 中危 | 按配置规则 |
| `build/`, `dist/` | 低危 | 完全可操作 |

## 6. IDE 集成安全

### 6.1 VSCode 扩展安全

当 Frees Agent 作为 VSCode 扩展运行时，需要考虑以下安全点：

```
VSCode 扩展安全
│
├── Extension 权限
│   ├── 使用 VSCode 的 Extension 权限模型
│   ├── 声明最小 required API
│   └── 不请求不必要的权限
│
├── Workspace Trust
│   ├── 仅在受信任的工作区启用完整功能
│   ├── 不受信任的工作区只读模式
│   └── 切换工作区时重置权限状态
│
├── 文件操作安全
│   ├── 使用 VSCode 的 TextEdit API（而非直接写文件）
│   ├── 编辑前校验文件 hash 防止冲突
│   └── 提供 diff 视图让用户预览修改
│
├── Terminal 集成
│   ├── 使用 VSCode 的 Terminal API
│   ├── 不在终端执行未经确认的命令
│   └── 所有终端操作可追溯
│
└── 数据保护
    ├── 不在剪贴板中记录敏感数据
    ├── 会话信息不持久化存储
    └── 扩展更新时保留用户配置
```

### 6.2 IDE 集成安全检查清单

```
□ Extension 是否只请求了最小必要权限？
□ 是否在不受信任的工作区降低了功能等级？
□ 文件编辑是否提供了 diff 预览？
□ 终端命令执行前是否确认？
□ API Key 是否安全存储（secret storage）？
□ 扩展更新会保留用户配置吗？
□ 是否有 kill switch 禁用所有 Agent 操作？
□ 日志是否记录了所有高风险操作？
□ 用户是否可以一键撤销所有授权？
```

## 9. 容器隔离

### 9.1 Docker 隔离参考

当需要更强的隔离时，可以在 Docker 容器中运行 Frees Agent 的模型服务和工具执行：

```dockerfile
# Dockerfile.isolated — 隔离运行环境
FROM node:20-alpine AS base

# 创建非 root 用户
RUN addgroup -S frees && adduser -S frees -G frees

# 安装 Frees Agent
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .

# 切换到非 root 用户
USER frees

# 安全选项
# --cap-drop=ALL 移除所有特权能力
# --read-only 只读文件系统
# --network=none 禁用网络（如果需要）
ENTRYPOINT ["node", "src/cli.js"]
```

运行命令：

```bash
# 最小权限运行
docker run --rm \
  --cap-drop=ALL \
  --read-only \
  --tmpfs /tmp \
  --tmpfs /home/frees/.frees-agent \
  -v /path/to/workspace:/workspace:ro \
  frees-agent:latest \
  chat . --model claude-sonnet-4-5

# 需要网络访问时
docker run --rm \
  --cap-drop=ALL \
  --cap-add=NET_RAW \
  --read-only \
  --tmpfs /tmp \
  -v /path/to/workspace:/workspace:rw \
  -e ANTHROPIC_API_KEY \
  frees-agent:latest \
  edit . --task "fix bugs"
```

## 10. 电脑控制能力与风险评估

### 10.1 各操作系统权限详解

#### macOS 权限体系

| 权限类型 | 适合场景 | 风险等级 | 用户授权方式 |
|---------|---------|---------|------------|
| 辅助功能 (Accessibility) | 控制键盘和鼠标，自动化操作界面 | 高 | 系统偏好设置 > 隐私 > 辅助功能 |
| 自动化 (Automation) | 控制其他应用，让一个应用驱动另一个应用 | 高 | 系统偏好设置 > 隐私 > 自动化 |
| 完全磁盘访问 (Full Disk Access) | 读取系统级文件，跨目录访问数据 | 高 | 系统偏好设置 > 隐私 > 完全磁盘访问 |
| 屏幕录制 (Screen Recording) | 屏幕截图、界面交互 | 高 | 系统偏好设置 > 隐私 > 屏幕录制 |
| 输入监控 (Input Monitoring) | 监听键盘事件 | 高 | 系统偏好设置 > 隐私 > 输入监控 |
| 文件和文件夹 (Files and Folders) | 访问指定目录文件 | 中 | 系统偏好设置 > 隐私 > 文件和文件夹 |

#### Windows 权限体系

| 权限类型 | 适合场景 | 风险等级 | 用户授权方式 |
|---------|---------|---------|------------|

| PowerShell 执行策略 | 运行脚本，自动化任务 | 中 | PowerShell Set-ExecutionPolicy |
| 管理员权限 | 系统级操作 | 高 | UAC 提权 |
| 文件系统权限 | 访问项目文件 | 低 | 文件系统 ACL |
| Windows 防火墙 | 网络访问控制 | 中 | Windows Defender Firewall |

## 11. 安全最佳实践总结

### 11.1 安全配置检查清单

```
□ 默认权限等级已经设为最低合理级别？
□ 所有高风险操作都有用户确认提示？
□ 敏感文件列表已经配置完善？
□ 危险命令拦截规则已经开启？
□ 审计日志已经启用并有轮转策略？
□ 网络访问已经设为默认拒绝？
□ API Key 使用了环境变量而非硬编码？
□ 定期审查了审计日志？
□ 了解了 OWASP LLM Top 10 威胁？
□ 用户知道如何撤销权限？
□ 有紧急停止所有 Agent 操作的能力？
□ 定期更新依赖以修复已知漏洞？
```

### 11.2 安全事件响应流程

```
1. 发现异常 ──── 暂停所有 Agent 操作
2. 评估影响 ──── 查看审计日志，确定影响范围
3. 切断权限 ──── 撤销所有 Agent 权限
4. 修复漏洞 ──── 更新配置或代码
5. 重新授权 ──── 降级后重新授权
6. 事后复盘 ──── 分析原因，更新安全策略
```
