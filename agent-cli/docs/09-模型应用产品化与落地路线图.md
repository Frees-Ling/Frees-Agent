# 模型应用、产品化与落地路线图

## 1. 不要只盯着训练

很多团队一谈 AI 就只想到"训练模型"，但真正决定产品是否好用的因素还包括：

| 因素 | 重要性 | 说明 |
|------|-------|------|
| 模型选择 | 核心 | 选择合适的模型基座比从头训练更高效 |
| 系统提示词 | 高 | 精心设计的提示词可以大幅提升效果 |
| 工作流设计 | 高 | Agent 的执行流程决定了任务完成度 |
| 工具调用 | 高 | 工具定义的质量直接影响 agent 能力边界 |
| 记忆系统 | 中高 | 长期记忆让模型更懂用户 |
| RAG | 中高 | 检索增强让模型拥有外部知识 |
| 长对话压缩 | 中 | 控制上下文窗口消耗，降低成本 |
| 权限控制 | 中 | 保证系统安全，防止误操作 |
| 评测与监控 | 高 | 没有监控就无法持续优化 |
| 成本控制 | 中高 | API 调用成本在规模化后急剧上升 |

## 3. API Gateway 设计

当需要对外提供服务时，API Gateway 是必备组件。

### 3.1 Gateway 功能清单

| 功能 | 说明 | 优先级 |
|------|------|-------|
| 请求路由 | 将请求分发到不同模型/服务 | P0 |
| 速率限制 | 防止滥用，控制使用频率 | P0 |
| 认证鉴权 | API Key / JWT 验证 | P0 |
| 请求日志 | 记录所有请求用于审计 | P0 |
| 负载均衡 | 在多个后端实例间分发请求 | P1 |
| 请求缓存 | 缓存相同请求的结果 | P1 |
| 熔断降级 | 后端故障时优雅降级 | P1 |
| 计费计量 | 按 token 或请求量计费 | P2 |
| 灰度发布 | 新模型的逐步放量 | P2 |

### 3.2 简单 Gateway 实现示例

```javascript
// api-gateway.js — 简单 API 网关示例
class APIGateway {
  constructor() {
    this.routes = new Map();
    this.rateLimits = new Map();
    this.apiKeys = new Set();
  }

  registerRoute(path, handler, options = {}) {
    this.routes.set(path, { handler, options });
  }

  registerApiKey(key) {
    this.apiKeys.add(key);
  }

  authenticate(request) {
    const apiKey = request.headers['x-api-key'];
    if (!this.apiKeys.has(apiKey)) {
      return { ok: false, error: 'Unauthorized' };
    }
    return { ok: true };
  }

  async rateLimit(clientId) {
    const now = Date.now();
    const windowMs = 60000; // 1 分钟窗口
    const maxRequests = 60;  // 每分钟 60 次

    if (!this.rateLimits.has(clientId)) {
      this.rateLimits.set(clientId, []);
    }

    const timestamps = this.rateLimits.get(clientId);
    const recent = timestamps.filter(t => now - t < windowMs);

    if (recent.length >= maxRequests) {
      return { ok: false, retryAfter: Math.ceil((recent[0] + windowMs - now) / 1000) };
    }

    recent.push(now);
    this.rateLimits.set(clientId, recent);
    return { ok: true };
  }

  async handleRequest(request) {
    // 1. 日志
    console.log(`[${new Date().toISOString()}] ${request.method} ${request.path}`);

    // 2. 认证
    const auth = this.authenticate(request);
    if (!auth.ok) return { status: 401, body: auth };

    // 3. 速率限制
    const clientId = request.headers['x-client-id'] || 'anonymous';
    const limit = await this.rateLimit(clientId);
    if (!limit.ok) {
      return { status: 429, body: { error: 'Rate limited', retryAfter: limit.retryAfter } };
    }

    // 4. 路由
    const route = this.routes.get(request.path);
    if (!route) return { status: 404, body: { error: 'Not found' } };

    // 5. 执行
    try {
      const result = await route.handler(request.body);
      return { status: 200, body: result };
    } catch (err) {
      console.error(`Handler error:`, err);
      return { status: 500, body: { error: 'Internal error' } };
    }
  }
}
```

### 4.2 实现监控埋点

```javascript
// monitoring.js — 轻量监控埋点
class Monitor {
  constructor() {
    this.metrics = new Map();
    this.logs = [];
    this.MAX_LOGS = 10000;
  }

  // 计时器
  startTimer(name) {
    const key = `timer:${name}`;
    this.metrics.set(key, { start: Date.now() });
  }

  endTimer(name) {
    const key = `timer:${name}`;
    const data = this.metrics.get(key);
    if (!data) return;
    const duration = Date.now() - data.start;
    this.recordLatency(name, duration);
    this.metrics.delete(key);
    return duration;
  }

  // 延迟记录
  recordLatency(name, ms) {
    if (!this.metrics.has(`latency:${name}`)) {
      this.metrics.set(`latency:${name}`, []);
    }
    this.metrics.get(`latency:${name}`).push(ms);
  }

  // 计数
  increment(name, value = 1) {
    if (!this.metrics.has(`count:${name}`)) {
      this.metrics.set(`count:${name}`, 0);
    }
    this.metrics.set(`count:${name}`, this.metrics.get(`count:${name}`) + value);
  }

  // 日志
  log(level, message, data = {}) {
    const entry = {
      timestamp: new Date().toISOString(),
      level,
      message,
      ...data
    };
    this.logs.push(entry);
    if (this.logs.length > this.MAX_LOGS) {
      this.logs.shift();
    }
    if (level === 'error') {
      console.error(JSON.stringify(entry));
    }
  }

  // 获取统计摘要
  getSummary() {
    const summary = {};
    for (const [key, values] of this.metrics) {
      if (key.startsWith('latency:')) {
        const nums = values;
        const sorted = [...nums].sort((a, b) => a - b);
        summary[key] = {
          count: nums.length,
          avg: nums.reduce((a, b) => a + b, 0) / nums.length,
          p50: sorted[Math.floor(sorted.length * 0.5)],
          p95: sorted[Math.floor(sorted.length * 0.95)],
          p99: sorted[Math.floor(sorted.length * 0.99)],
          max: sorted[sorted.length - 1]
        };
      } else if (key.startsWith('count:')) {
        summary[key] = values;
      }
    }
    return summary;
  }
}

module.exports = { Monitor };
```

### 6.3 Token 节省示例

```javascript
// token_saver.js — Token 节省策略实现
class TokenSaver {
  constructor(maxContextTokens = 32000) {
    this.maxContextTokens = maxContextTokens;
  }

  // 消息历史裁剪：保留首尾 N 条
  trimMessages(messages, keepHead = 20, keepTail = 20) {
    if (messages.length <= keepHead + keepTail) return messages;

    const head = messages.slice(0, keepHead);
    const tail = messages.slice(-keepTail);

    return [
      ...head,
      { role: 'system', content: `[已省略中间 ${messages.length - keepHead - keepTail} 条消息]` },
      ...tail
    ];
  }

  // 工具结果截断
  truncateToolResult(text, maxChars = 2000) {
    if (text.length <= maxChars) return text;
    return text.slice(0, maxChars) +
      `\n...(已截断，原长度 ${text.length} 字符，保留前 ${maxChars} 字符)`;
  }

  // 会话摘要（调用 LLM 压缩）
  async summarizeConversation(messages, llmClient) {
    const conversation = messages
      .map(m => `${m.role}: ${m.content?.slice(0, 500)}`)
      .join('\n');

    const summary = await llmClient.chat({
      messages: [{
        role: 'user',
        content: `请用 3-5 句话总结以下对话的关键信息：\n\n${conversation}`
      }],
      maxTokens: 200
    });

    return summary;
  }
}
```

| 指标 | 定义 | 目标 | 测量方式 |
|------|------|------|---------|
| 可用性 (Uptime) | 服务正常响应时间比例 | 99.9% (每月宕机 < 43min) | 健康检查端点 |
| 响应时间 (P95) | 95% 请求的响应时间 | < 5 秒 | 端到端监控 |
| 错误率 | 失败请求比例 | < 1% | 日志分析 |
| 吞吐量 | 每分钟处理请求数 | 根据业务定义 | 计数监控 |
| 新鲜度 | 模型/数据更新时间 | < 24 小时 | 版本跟踪 |

### 7.2 SLA 常见补偿策略

```yaml
sla_compensation:
  tier_1: 99.9% ~ 99.5%
    compensation: "次月 10% 费用减免"
  tier_2: 99.5% ~ 99.0%
    compensation: "次月 25% 费用减免"
  tier_3: 低于 99.0%
    compensation: "次月 50% 费用减免"
```

## 8. 版本管理策略

### 8.1 模型版本管理

```
版本命名规范：

<模型名>@<主版本>.<次版本>.<补丁>-<阶段>

示例：
  qwen-coder@2.5.0-stable
  claude-sonnet@4.5.0-stable
  deepseek-coder@1.0.0-beta
  fine-tuned-model@1.2.3-private

阶段：
  - alpha:   内部开发版本
  - beta:    公开测试版本
  - rc:      候选发布版本
  - stable:  稳定版本
  - deprecated: 已弃用（仍可用但不再维护）
  - sunset:  即将下线
```

### 8.2 Prompt 版本管理

Prompt 也需要版本管理。一个好的实践是将所有 prompt 存入代码库：

```
prompts/
├── v1/
│   ├── chat-system.md
│   ├── edit-system.md
│   └── tool-descriptions.md
├── v2/
│   ├── chat-system.md
│   └── edit-system.md
└── CHANGELOG.md
```

每个版本需要记录：
- 改动内容
- 改动原因
- 影响范围
- A/B 测试结果

### 8.3 向后兼容策略

```yaml
backward_compatibility:
  api:
    - URL 路径不轻易变更
    - 新增参数使用可选字段
    - 废弃 API 至少维护 6 个月
    - 提供迁移指南

  model:
    - 旧模型保留至少 3 个月
    - 模型切换前通知用户
    - 提供回滚选项

  config:
    - 配置格式向前兼容
    - 旧配置自动升级到新格式
    - 变更前写入迁移脚本
```

## 10. 常见问题与最佳实践

### 10.1 落地过程中的常见陷阱

| 陷阱 | 表现 | 预防 |
|------|------|------|
| 过度工程化 | 在 MVP 前就追求完美架构 | 先跑通再优化 |
| 忽视成本 | 全量用最贵的模型 | 按任务分级使用模型 |
| 缺少评测 | 无法判断新版本是否更好 | 建立自动化评测 pipeline |
| 版本混乱 | 不知道在用什么版本 | 使用版本管理策略 |
| 安全后置 | 上线后发现安全漏洞 | 安全设计从第一天开始 |
| 模型切换 | 换了模型后发现行为不一致 | 建立 prompt 和工具的多模型兼容 |
