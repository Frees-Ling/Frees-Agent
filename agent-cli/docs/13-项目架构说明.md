# Frees Agent 项目架构说明

## 1. 架构目标

`Frees Agent` 的目标不是做成一次性脚本，而是做成一个可以持续维护和拓展的终端 AI Agent 工程。

所以项目结构强调：

- 命令清晰
- 模型清晰
- 记忆清晰
- 工作区能力清晰
- 扩展点清晰

## 2. 核心分层

```
src/
├── cli.js              # 入口：路由 → 命令
├── commands/           # 命令层
├── agent/              # Agent 循环 + 工具系统
├── model/              # 模型接入
├── workspace/          # 工作区扫描 + 文件操作
├── memory/             # 记忆系统
├── shell/              # Shell 执行框架
├── skills/             # Skill 系统
├── ui/                 # 展示层
├── system/             # 系统能力
└── utils/              # 工具层
```

### 命令层

负责：
- 解析参数
- 调用服务
- 输出结果

目录：
- `src/commands/`
  - `chat.js` — 终端聊天（含流式回复、记忆、工具循环）
  - `edit.js` — Agent 式自动代码编辑
  - `complete.js` — 基于工作区上下文的代码补全
  - `doctor.js` — 系统诊断与连通性检查
  - `config.js` — 配置文件初始化与查看
  - `memory.js` — 记忆管理（查看/清理/会话/合并）
  - `docs.js` — 内置中文文档查看
  - `permissions.js` — 系统权限引导
  - `skills.js` — Skill 文件加载与查看
  - `compact.js` — 手动触发会话摘要压缩
  - `cost.js` — Token 用量统计与上下文占用率
  - `files.js` — 工作区索引文件列表

### Agent 循环层

负责管理 AI Agent 的运行循环、工具调用和执行编排。

目录：
- `src/agent/`
  - `chat-tool-loop.js` — 聊天模式工具循环
    - 工具调用 → 结果截断（保持结构，content/stdout 优先裁剪）
    - EAGAIN/ETIMEDOUT/ECONNREFUSED 自动重试（最多 2 次）
    - 消息历史裁剪（保留首尾各 20 条）
  - `edit-loop.js` — 编辑模式 Agent 循环
    - 最大步数控制（默认 14 步）
    - JSON 动作解析（type: tool / type: final）
    - 输出结果截断（8000 字符上限）
  - `orchestration.js` — 工具编排
    - 读写工具分区：只读工具并发执行，写入工具串行执行
    - 并发控制（默认 5 并发）
    - 结果格式化
  - `prompts.js` — 系统提示词
    - TOOL_DESCRIPTIONS：10 种工具的详细描述（参数、行为、返回值）
    - CHAT_TOOL_SYSTEM_PROMPT：聊天模式的工具使用指引
    - EDIT_AGENT_SYSTEM_PROMPT：编辑模式的工具使用指引
  - `tools.js` — 统一工具箱
    - 别名映射：glob→list_files, grep→search_text, read→read_file 等
    - 工具：list_files, search_text, read_file, write_file, replace_in_file, web_fetch, bash
    - bash 工具集成 validateShellCommand 安全校验
    - MCP 工具集成（动态加载）
    - getToolList() 返回标准 tool schema

### 能力层

负责：
- 模型接入
- 工作区扫描
- 记忆
- skill
- 系统能力

目录：
- `src/model/` — 模型接入
- `src/workspace/` — 工作区
  - `indexer.js` — 递归扫描，24MB 预算保护
  - `queries.js` — 文件读取含行号标注、智能字符串匹配（引号归一化+邻近行提示）
  - `context.js` — 相关文件上下文组装
- `src/memory/` — 记忆系统
  - `store.js` — 核心：加载/保存/合并/迁移，跨设备同步
  - `heuristics.js` — 启发式提取：姓名、目标、偏好正则匹配
  - `vector.js` — 256 维 FNV-1a 向量化，CJK 感知 n-gram 分词
  - `ingest.js` — 语义提取管线
  - `tasks.js` — 任务记忆加载与合并
- `src/skills/` — Skill 文件系统
- `src/shell/` — Shell 执行框架
  - `shell-exec.js` — 安全 shell 执行，危险命令拦截，AbortController 超时

### 展示层

负责：
- banner
- 状态输出
- 交互提示

目录：
- `src/ui/`

### 工具层

负责：
- 通用工具函数（零外部依赖）
- ripgrep 搜索、文本截断、主题渲染、树形渲染
- 会话压缩、token 统计
- Git 仓库查询、文件类型检测

目录：
- `src/utils/`
  - `slug.js` — Agent ID 哈希、语义化 slug 生成（形容词-动词-名词组合词）
  - `sleep.js` — AbortSignal 感知的延迟与超时
  - `which.js` — 跨平台可执行文件查找
  - `uuid.js` — Agent ID 生成与 UUID 校验
  - `memoize.js` — 内联 Map 缓存
  - `ripgrep.js` — 系统 rg 检测、正则搜索、流式结果、EAGAIN 重试
  - `theme.js` — 4 主题系统（dark/light/dark-ansi/light-ansi），ANSI 转换
  - `truncate.js` — ANSI 感知文本截断，CJK 安全
  - `treeify.js` — Unicode 树形渲染，循环引用检测
  - `json.js` — JSON 安全解析，首个 JSON 对象提取
  - `files.js` — 文件类型检测（二进制/文本嗅探），格式化字节数
  - `git.js` — Git 仓库状态查询
  - `ultraplan/keyword.js` — 增强规划关键词检测

## 3. 关键架构特性

### 零外部依赖
所有工具函数仅使用 Node.js 内置模块，无 npm 依赖。

### 记忆系统分层
- **启发式提取**（heuristics.js）：正则匹配即时提取姓名/目标/偏好
- **语义提取**（ingest.js）：通过 LLM 调用进行结构化抽取
- **向量索引**（vector.js）：256 维 FNV-1a 哈希嵌入，余弦相似度召回
- **持久化存储**（store.js）：JSON 文件 + 跨设备同步 + 去重压缩

### Agent 工具安全
- 只读工具可并发执行，写入工具串行执行
- bash 工具内置 7 种危险命令拦截
- 工具结果自动截断保护上下文窗口

## 4. 为什么这样拆

如果以后你要继续增加：

- RAG
- 多智能体
- IDE 集成
- 电脑控制
- 更强权限系统

这种结构会比把所有逻辑堆在一个文件里更容易维护。
